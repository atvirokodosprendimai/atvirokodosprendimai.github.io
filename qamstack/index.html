What it is

Three failures. Three tools.

The QAM Stack is three independent open-source tools that make an AI coding agent's work verifiable. Each came from one real failure where an agent reported success and had done nothing. None of them makes the model smarter — they make it accountable.

AAI Agent Memory — decisions and rejects outlive the session.

The three

What each one does.

Q

Quality Harness

Gates, not vibes

A Claude Code plugin: 16 skills, 11 gate binaries. Skills carry the workflow. Binaries enforce it — a skill can be argued with, an exit code cannot.

For you: Claude cannot mark work done without evidence you can re-run.
  • adr-lint exits 1 on a record that claims done with no evidence line.
  • adr-judge always exits 0, by design — advice never enters the evidence chain.
  • mutation-audit breaks a mechanism to see if any test notices.

A

AI Agent Memory

The reasoning survives

An MCP server your agents read and write. Code shows what it does now. It cannot show what was rejected — a fix looks identical to code that was always right.

For you: stop re-briefing Claude every morning.
  • Shared across Claude, Codex and CI — one memory, not one per session.
  • Temporal graph — superseding a fact ends the old and starts the new in one transaction.
  • Honest reads — truncation and three kinds of empty answer come back as fields.

M

MultiPath Read/Write

Edits with a receipt

One Go binary. Many ranges read, many edits applied, one call, all or nothing, a verdict per hunk. No server, no daemon — a hook can name it and read its output.

For you: a half-applied refactor stops being possible. See the benchmark above.
  • Atomic — one failed hunk aborts the plan, tree untouched.
  • Checksum ledger — a file changed behind Claude's back is refused, not clobbered.
  • --check runs your tests scoped to what changed; exit codes separate the causes.

Answers

Straight answers.

Do I have to adopt all three?

No. They share a philosophy, not a runtime. Each installs on its own and is useful on its own — most people start with whichever failure is costing them most this week.

Is this Claude-only?

No. Quality Harness ships as a Claude Code plugin, but its gates are standalone binaries you can call from any pipeline. Agent Memory is an MCP server and its installer wires both CLAUDE.md and AGENTS.md, so Claude Code and Codex read the same protocol. mrw is a plain CLI binary any agent or human can run.

Does my code or memory leave my machine?

Only if you choose that. The Quality Harness gates are local binaries. Agent Memory runs hosted if you want zero ops, or entirely on your own infrastructure with Docker Compose if you do not. mrw is a local binary.

Will this slow my agent down?

The opposite, in the cases that matter. The one thing that costs you time is a gate refusing bad work — and that is time you were going to spend anyway, later, in production. Recalled memory replaces whole rounds of re-derivation, and batched reads and writes cut tool calls and context spend.

What does it cost?

The tools are open source. Self-hosting costs you whatever the box costs. The hosted memory service is there for teams that would rather not run one.

What exactly is the QAM Stack?

Three independent open-source tools for AI coding agents: Quality Harness (gates that exit non-zero on unproved work), AI Agent Memory (an MCP server that remembers decisions across sessions) and MultiPath Read/Write (batched, atomic, receipted file edits). Q, A and M. They share a philosophy — make silent failure loud — not a runtime.

Is this related to quadrature amplitude modulation?

No. That QAM is a signal modulation scheme used in telecoms. This QAM is an acronym for the three tools on this page: Quality Harness, Agent Memory, MultiPath Read/Write.
