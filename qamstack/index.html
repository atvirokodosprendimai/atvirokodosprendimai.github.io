Q

Quality Harness

Make “done” a thing a machine can check.

A Claude Code plugin that turns decisions, specs and reviews into executable records. Sixteen skills carry the workflow. Eleven binaries enforce it — because a skill can be talked past, and a non-zero exit cannot.

  • Your architecture decisions get teeth. adr-write proposes, adr-execute works it task by task, adr-verify records the tool-written evidence, adr-retire archives without erasing authority.
  • Gates that actually refuse. adr-lint exits non-zero on a record that claims done without proof. adr-debt sweeps a whole corpus for deferred promises nobody kept.
  • Opinion kept out of the evidence chain. adr-judge rates clarity and always exits 0 by design, so a prose heuristic can never masquerade as a proof.
  • Reviews with a verdict, not vibes. review, mutation-audit (break a mechanism on purpose, see if any test notices), consensus, plus cross-lineage codex-review for a second opinion from a different model family.

A

AI Agent Memory

Stop paying for the same context twice.

A memory palace your whole team writes to and reads from across sessions, served over MCP. Your repo shows what the code does now. It cannot show what was rejected, what was abandoned, or what last week's agent got wrong. This does.

  • Every agent shares one brain. Claude, Codex, your CI bot — same palace, same decisions, no re-briefing.
  • Organised so recall stays sharp. Wings are projects, rooms are aspects (decisions, incidents, reviews), drawers are verbatim memories. Craft that outlives any one repo lives in a shared wing every project reads.
  • A temporal knowledge graph, not a note pile. Facts as subject → predicate → object with validity windows; superseding one ends the old value and starts the new in a single transaction, so no query ever sees both or neither.
  • It tells you what it did not tell you. Truncation, staleness and three distinct kinds of empty answer come back as fields — a fragment can never pass for a whole memory.
  • Your conventions, served live. Team skills authored once and loaded by every agent, so a stale local copy never wins the argument.
  • Your data, your infrastructure. Run it hosted, or bring the whole thing up with Docker Compose behind your own firewall.

M

MultiPath Read/Write

Ten-file edits in one call. With receipts.

mrw reads many file ranges and applies many edits in one call — all or nothing, with a verdict per hunk. One small Go binary. No server, no daemon, nothing to operate — so a hook can name it and read its receipt.

  • Fewer calls, smaller context, faster turns. On a four-site, four-file edit: 8 tool calls and ~39 KB the conventional way versus 2 calls and ~3.8 KB with mrw — and the saving grows with every extra site.
  • Partial success is impossible. One failed hunk aborts the plan; its siblings report skipped and your working tree is untouched.
  • A receipt, not a summary. Every hunk reports applied or refused, and the --json output names each file touched — including the ones whose edits failed.
  • It refuses to clobber. A SHA-256 read-before-modify ledger, written on read and on write, so a file changed behind the agent's back gets refused instead of overwritten.
  • The check rides along. mrw check scopes your project's own test command to what you touched, and separate exit codes distinguish the write failed from the check failed from the check could not run.

Straight answers

The questions you were about to ask.

Do I have to adopt all three?

No. They share a philosophy, not a runtime. Each installs on its own and is useful on its own — most people start with whichever failure is costing them most this week.

Is this Claude-only?

No. Agent Memory is an MCP server and its installer wires both CLAUDE.md and AGENTS.md, so Claude Code and Codex read the same protocol. mrw is a plain CLI binary any agent or human can run. Quality Harness ships as a Claude Code plugin, but its gates are standalone binaries you can call from any pipeline.

Does my code or memory leave my machine?

Only if you choose that. mrw is a local binary and the Quality Harness gates are local binaries. Agent Memory runs hosted if you want zero ops, or entirely on your own infrastructure with Docker Compose if you do not.

Will this slow my agent down?

The opposite, in the cases that matter. Batched reads and writes cut tool calls and context spend, and recalled memory replaces whole rounds of re-derivation. What does cost you time is a gate refusing bad work — which is time you were going to spend anyway, later, in production.

What does it cost?

The tools are open source and MIT licensed. Self-hosting costs you whatever the box costs. The hosted memory service is there for teams that would rather not run one.
