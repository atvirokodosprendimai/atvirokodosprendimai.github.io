MultiPath Read/Write · mrwThe guarantee layer for coding agents.

Your agent reads and edits files through mrw. A batch of edits lands whole or not at all, it can only change lines it was shown, and every edit comes back with a result. One free binary, for any shell or MCP host.

Install → Measured on Claude
four guarantees
  • All or nothing
    Edits across many files land together, or none of them do.
  • Only lines it was shown
    mrw refuses to change a line the agent hasn't been shown, unless the edit quotes it exactly or you override with --force. It keeps track line by line, not file by file.
  • A result for every edit
    Each edit reports on its own whether it applied.
  • Paths that resolve
    mrw works only on files under the folder you point it at. A path, link or Windows junction that leads outside is refused, it won't write inside .git, and when it can't find a file it says which path it looked for.

Measured on Claude

It also cost less. Whether solving held up is not settled.

On SWE-bench Verified with Claude Opus 5.5 and Sonnet 5.5, mrw cost 19% and 7% less than the native tools at 99% confidence. The pre-registered test could not rule out a small drop in solving, so the registered verdict is inconclusive.

How it's judged

A bar set before the first run.

The bar is in ADR-156; every verdict is in RESULTS.md, exactly as the analysis printed it.

the bar · ADR-156
  • PAYS
    Cost down 10% or more, its interval wholly below zero, and solving no more than 5 points worse at the interval's low end.
  • LOSES
    Cost clearly up, or solving clearly down.
  • INCONCLUSIVE
    Anything else.
  • Why not PAYS
    Both cost intervals lie wholly below zero. But solving's interval reaches −6.7 points on Opus and −8.7 on Sonnet, past the −5 the bar allows, and Sonnet's −7.0% is short of the 10% saving.
  • Earlier stages
    On this project's own tasks, every stage was INCONCLUSIVE except Stage 4 on mrw v1.66.0, which LOSES at cost +17.1% [+9.6%, +24.7%].

Q&A

Questions people ask.

Every question about the benchmark, answered in full: docs/bench/FAQ.md.

9 questions
What is mrw?

A free command-line tool, and MCP server, that your coding agent uses to read and edit files. It reads many parts of many files in one call and applies many edits in one call, all or nothing, with a result for every edit. MIT licence, one binary, no network call except mrw version --check-latest.

“Only lines it was shown”: what exactly does that cover?

mrw remembers which lines it showed the agent, and refuses an edit to any other line. Lines a read hid or cut short count as not shown. The exceptions: a file mrw just wrote is known in full; an edit that quotes the old lines exactly is checked against the file instead; a search-and-replace covers the lines it plans; with the optional read hook, lines the host's own Read tool showed count too; and --force overrides the refusal. One known gap is open: issue #602.

Don't other tools do all-or-nothing edits too?

Yes, several now do. What we haven't found elsewhere, in any tool or paper, is the line-by-line read check: the guards we know of only notice whether a whole file changed, by its timestamp.

What exactly was compared?

A is Claude Code 2.1.302 with its own file tools (Bash, Read, Edit, Write, Glob, Grep). B is the same CLI with Bash, Glob and mrw v1.68.0 in place of Read, Edit, Write and Grep. Same prompt, model, machine and 1,200-second budget, one attempt per task each.

It's cheaper. Why is the verdict inconclusive?

The bar, set before any run, asks for two things: a cost saving, and no more than a small drop in solving. Both cost savings are clear. But 191 tasks can't measure solving precisely enough to rule out a drop of a few points, so the test can't say “pays”. We report the verdict the bar gives, not the one we'd like.

Does the saving hold for Codex, Cursor or other agents?

Not measured, so we make no claim. mrw runs under any shell or MCP host, but the numbers are for Claude Code 2.1.302 with Opus 5.5 and Sonnet 5.5 only, and the same tool change can lower cost for one agent and raise it for another.

Could the agent run the tests?

No, in either arm. The checkouts had the code but not the test dependencies, so the agent fixed each bug from the issue text alone and the harness graded it afterwards. That is the main limit of this measurement.

Does mrw sandbox the commands it runs?

No. mrw run and --then-sh run shell commands as you, with your permissions. Allowing mrw in your agent allows that too.

Who makes it?

Atviro kodo sprendimai (Lithuanian for “open-source solutions”). mrw is new: its first release is from 2026-08-31, and the releases page lists every version since. That is why the evidence is laid out rather than asserted.

Install

One binary. No daemon, no account.

One call reads many ranges across many files; one call applies many edits across them, each with its own verdict. A plan that fails validation writes nothing, because a write that changed nothing is invisible.

Homebrew · Mac and Linux · v1.83.0

The easiest way in. The last line checks you got this version, not an older copy installed some other way.

Formula → 
$ brew tap atvirokodosprendimai/tap
$ brew install atvirokodosprendimai/tap/mrw
$ "$(brew --prefix)/bin/mrw" version
v1.83.0 (3a97083)

# to update later
$ brew update
$ brew upgrade atvirokodosprendimai/tap/mrw
or download · v1.83.0 · MIT

One file, nothing else to install. Windows: mrw-windows-amd64.exe. It passes our automated tests, but testing of the downloaded file itself isn't finished.

v1.83.0 release → GitHub →

since v1.77 · less noise for your agent

A test run can print thousands of lines. Now your agent gets a short summary instead, and the full output waits in a file if it needs it. Note that mrw run runs the command as you, with your permissions.

# a short summary instead of the whole output
$ mrw run 'go test ./...'

# only the values you ask for
$ mrw read --json-path '$.name,$.scripts.build' package.json

# a file's outline before its contents
$ mrw read --outline cmd/mrw/main.go README.md
since v1.77 · shorter answers

Skip repeated lines, comments and very long lines. What was skipped stays safe: the agent has to read it properly before it can change it.

# fold repeats, stop after 20 matches
$ mrw read --grep TODO --fold --max-matches 20 .

# skip comments, shorten long lines
$ MRW_MAX_COLS=160 mrw read --no-comments main.go

# a shorter result when an edit succeeds
$ mrw write --terse plan.mrw
